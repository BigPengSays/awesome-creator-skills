# Requirements Ledger

Read this file only when modifying the skill. Treat the current `SKILL.md` as the runtime source of truth and this ledger as a regression checklist. A new request adds or refines behavior; it removes an older requirement only when the user says so explicitly.

## Persistent Invariants

- Resolve one stable execution profile from advertised capabilities before intake, never from a product name or user selection. Use `codex-full` only when the exact callable `codex_app__load_workspace_dependencies`, local script execution, and a readable generated-image path are available; preserve its existing dependency lookup, Pillow probe, same-resolution finalization script, report check, and finalized PNG output. Otherwise, when image generation is available, use `portable-direct`: skip the Codex dependency tool, all Python/Pillow discovery, local scripts, file conversion, post-processing, and second image calls; compile finalizer-owned visual requirements into the one generation prompt and return that generated image directly after one visual check. If image generation is unavailable, stop once without recovery attempts.
- Generate one final image only, hide the internal prompt, avoid automatic retries, and keep both profiles to one reference inspection, one recipe, one generation, and one quality check. Only `codex-full` adds one same-resolution finalization pass; run it with the Python executable returned by `codex_app__load_workspace_dependencies`, verify it imports Pillow, and never use bare/system Python or install packages during generation.
- Before generation, resolve palette and aspect ratio through a strict two-stage intake. If both are missing, ask palette alone, then ratio alone in the next turn; if either is already supplied, skip that question; if both are supplied, generate immediately. Never generate while either field is missing or silently insert a default.
- Offer named palettes `经典`, `粉黛`, `极客01`, `极客02`, `复古01`, `复古02`, `游戏01`, `游戏02`, plus `如图`; keep their canonical colors in `references/palettes.md`. When asking for palette, `codex-full` displays the corrected bundled asset `assets/tait-crt-interface-color-card.png` and uses the text list only if rendering fails, while `portable-direct` uses the text list immediately without resolving or rendering the asset. For `如图`, derive a coherent 2-5-color palette from the uploaded image and use no more than five hues. Offer `3:4`, `4:3`, `9:16`, and `16:9`, while accepting a custom ratio.
- Generate directly at native resolution in the selected ratio. Never request or create a `480x720`/low-resolution precursor, resize, upscale, sharpen, denoise, or enhance.
- Support optional exact style presets `街头怪诞`, `巨像符号`, and `冷面几何`. Activate one only when the user explicitly selects it for the current generation; quoted, negated, compared, documented, or merely discussed names do not activate or persist. Retain an explicitly selected preset across palette/ratio intake turns, load its fixed style block and six locked subject-axis values from `references/style-presets.md`, and combine them with the actual subject roster and anchors without copying example props. Keep all nonlocked layout/interface axes adaptive. When no preset is explicitly selected, never ask, offer, recommend, or silently choose one; use the original blueprint and normal Variation Engine. Never blend presets, and let a later explicit preset selection replace an earlier retained one.
- Make the independently authored subject illustration the first visual priority. Before abstraction, identify and lock every visually prominent or interacting intended subject as a distinct roster member with spatial order, relative scale, interaction, contact/occlusion, and per-subject identity anchors. Preserve the roster unless the user explicitly selects one figure; never omit, fuse, swap, hybridize, or transfer traits between subjects. Keep only 3-5 semantic identity anchors per subject; treat at most one accessory or object as a signature anchor and discard source garment construction, prints, ornaments, jewelry inventories, folds, textures, facial modeling, and local contours. Rebuild from a text-only character brief rather than source geometry. Require one major proportion mutation, one major silhouette mutation, at least one additional structural change, and 2-3 exaggerated traits. Construct an angular, adult circa-1980s bitmap editorial caricature from 5-9 flat masses (prefer 5-7), with deliberate asymmetry, compressed anatomy, hard cutouts, negative space, and mask-like facial clusters. It may be strange, funny, awkward, grotesque, or charmingly ugly, but must remain loosely recognizable only through the selected anchors. Reject source-overlaid silhouettes, filtered or pixelated photographs, realistic pixel portraits, polished game sprites, anime/chibi or kawaii art, cute mascots, children's-book illustration, generic clip art, and clean vector-cartoon tracing.
- Preserve plausible hand topology within the simplified cartoon: bind every visible hand to the correct arm and wrist, maintain palm orientation, contact/occlusion, and any depicted finger count. When the grid is too coarse for separate fingers, use an intentional mitten/grouped silhouette rather than malformed pseudo-fingers. Reject detached, fused, inverted, penetrating, extra-fingered, or missing-fingered hands.
- Use one global content lattice across the entire frame. Derive square base cell `p` at roughly `short edge / 384`, and draw subject, windows, borders, text, icons, cursor, charts, and any checkerboard with that same complete `p x p` cell. Treat the approximately `30 x 30` subject rule as a contour/feature complexity budget, not a larger subject-only pixel size. Prefer curve-free horizontal/vertical runs, stair diagonals, chamfers, wedges, rectangles, and low-sided polygons. Permit only one or two indispensable large stepped arcs, each assembled from 3-6 straight segments; forbid flowing contours, repeated rounded features, chains of variable arcs, half, stretched, rectangular, rotated, shifted, cracked, stray, misaligned, antialiased, or smooth-transition subject cells and broken checker sequences. Keep CRT scanlines/noise as a finer surface layer, not content geometry.
- Show exactly one full primary wallpaper composition—one figure or one anchored group—behind windows. Keep it at least 50% of the canvas, normally 60%-80%. A group must contain every locked member once with identities and relationships intact. Do not duplicate the composition. Always include 1-3 feature-extraction windows with tight crops of distinctive partial elements; when multiple appear, every window must use a different feature, size, and aspect ratio. Magnification changes crop allocation, never the global pixel cell.
- Preserve 20%-30% connected open field. Use 3-6 windows with large/medium/small hierarchy, multi-quadrant distribution, 5%-20% overlap, balanced mass, top menu, one open French drop-down, and exactly one cursor. Avoid rigid rows, columns, equal windows, and one-sided weight.
- Use only the resolved named or derived 2-5-color palette; do not impose a universal polarity. Prefer bold adjacent solid-color planes. Checkerboard is optional and uses only the darkest and lightest colors; allow it solely for a necessary optical middle tone on a non-skin curved surface or to distinguish touching planes whose front/back relation is otherwise unclear. Keep it compact and connected. Forbid checkerboard on faces, necks, ears, hands, arms, legs, or any exposed skin, as well as decorative, scattered, or all-over checker texture. `codex-full` finalization must preserve authored checkerboard but never synthesize new checker cells; `portable-direct` must request the same behavior directly in generation without claiming deterministic enforcement. Allow no computed gray pixels, stipple, hatch, tonal gradients, or extra density levels.
- Keep hard bitmap glyphs, binary bloom, dense scanlines, noise, same-palette misregistration, vertical persistence, one sync disturbance, and mandatory radial barrel curvature/compression in the outer 10% of all four sides while protecting the inner 80%. Corners compress more than edge centers and long top/side lines visibly bow; flat rectangular output fails.
- Always place the exact lowercase signature `tait-crt-interface-skill` in the upper-right title bar using the same global bitmap grid/family as the left label rail. It is an immutable exception to user overrides and may not be omitted, renamed, translated, cropped, covered, hidden, or made illegible.
- Keep colors outside the resolved palette, more than five derived hues, modern UI, vector smoothness, computed gray, alpha, gradients, 3D, physical monitor housing, other logos, CTA, and long text out of the image.

## Variation and Compiler Structure

- Preserve the structure adapted from the Minimal Zine Poster approach: stable invariants -> first-principles prompt fields -> multi-axis Variation Engine -> fixed prompt shape -> workflow -> quality gate.
- Make variation alter visual grammar across subject placement/crop/coverage and window count/constellation/hierarchy, not merely random position.
- Let explicit user constraints override recipe choices without weakening invariants.
- Treat an exact named style preset as a fixed subject-style recipe: lock its crop/silhouette, coverage, cartoon treatment, caricature mutation, geometry grammar, and midtone map while leaving other axes variable. Expand crop/coverage only when necessary to preserve the complete anchored roster and interactions.

## Modification Protocol

1. Read the current skill, script, UI metadata, this ledger, and available earlier user modifications before editing.
2. Build an internal retained/changed/removed checklist. Treat removal as empty unless the user explicitly requests it.
3. Integrate changes into existing sections or refactor globally; do not append redundant prose.
4. Search the edited files for every persistent invariant and for stale contradictory wording.
5. Run the official skill validator and metadata checks; test scripts only when changed.
